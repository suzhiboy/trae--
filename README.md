# 知识漏洞侦探

一个面向高中数学的错答诊断网页：学生写下最终答案和推导步骤，页面定位出错的步骤、引用学生原句作为证据、给出补习顺序，再用一道变式题让学生自己验证。

核心演示（比较两份草稿 + 内置 12 题）只依赖本地规则与静态资源，不需要 API 密钥；首次打开需要加载页面自身的字体与插图，之后核心诊断可离线运行。评委可以在首页直接回答一个问题：

> **两个人都答了 2，他们错在同一步吗？**

## 阶段 1 新增：任意题诊断（AI 理解 + 本地复算）

首页在「比较两份草稿」之后新增 `#freeform` 入口。它可以接收题目文本、学生最终答案、学生步骤，也可以拍照或上传图片先做 OCR；识别结果回填后必须由学生确认、修改，再提交诊断。

- **命中内置 12 题**：仍走原规则引擎，不发请求，离线可用。
- **未命中**：调用服务端模型输出结构化 JSON（标准解法、正确答案、首个错误步骤序号、学生原句、错因、知识点、变式题+答案、置信度、可复算声明）。
- **本地核验层独立复算**：函数代入、四则运算/等式链、集合运算、一元二次方程根、等差数列求和。每条结论显示「已核验 / 冲突 / AI 推断，未核验」。
- **冲突处理**：AI 与复算不一致时，以复算结果为准；页面保留 AI 原答案作对照，并把总体结论降为需要复核。
- **不确定就说不确定**：自然语言、方程变形、含参讨论等无法独立复算的内容只标「AI 推断，未核验」，不冒充已核验。
- **降级**：超时、限流、断网、未配置模型都有明确提示；未配置时内置 12 题仍可离线使用。

> 当前验证状态：界面已切换到 FunctionWeb 并上线；核验逻辑用本地 mock 上游跑通，线上未配置 Key 时的降级提示正常；**真实火山方舟调用与线上 3 道非题库题截图待验证**。没有伪造的线上结果或准确率数据。

## 阶段 2 新增：任意题的变式验证与学习闭环

### 两道变式，先复算再展示

- `/api/freeform-diagnose` 现在返回 2 道同错因变式候选；不足时由 `POST /api/freeform-variants` 补充生成。
- 每道候选的答案必须由本地 `checkQuestionAnswer` 从题干独立复算通过后才允许展示；答案算错、无法复算、与已用题干重复的候选一律丢弃，最多两轮；仍不足 2 道就如实显示“没有找到可通过本地复算的变式”，不拿未核验题凑数。
- 当前可复算的变式题型：函数代入、纯数字算式、集合交并补、一元二次/一元一次方程求根、等差数列单项与前 n 项和。其他题型（三角、证明、含参讨论等）不会生成可展示变式。
- 变式卡片明确标注“题目由 AI 生成 · 答案通过本地独立复算”，并显示复算类型。

### 变式答错后再诊断

- 先由本地答案比对判定对错；只有答错才调用模型诊断变式作答，再与原诊断按知识节点、知识点文本对比。
- 结论只取三种：**错因很可能仍在** / **原错因未复现，出现新问题** / **无法可靠判断是否同一错因**。
- 界面标明“依据是两次 AI 诊断的知识点对比，未经独立核验”；证据不足或复算冲突时不硬判。
- 答对只写“本次变式答对（首次作答 / 第 N 次尝试）”，不推断长期掌握；修改答案或关键步骤会清除旧结论，重新提交重新判定。

### 汇总与教师视图

- `src/engine/session.ts` 新增 `summarizeDiagnoses(records)`，可汇总内置题与任意题诊断，合并去重知识节点和知识点文本；原 `summarizeSession` 行为不变。
- 自由题诊断记录保存在本机 `localStorage`（`kd:freeform:v1:records`，最多 30 条）；同一道题只保留最近一次诊断。页面显示合并薄弱点、补习顺序与历史记录。
- 练习会话报告与自由诊断记录都可导出 CSV；导出前需填写本机学生编号，未填写时按钮禁用，不编造编号。
- 新增 `#teacher` 教师视图：可粘贴多份 CSV，或导入本机已完成的真实报告；按错因聚合最常见的 3 个，显示对应学生编号。证据不足、答案正确、跳过/我不会的记录不计入错因统计。
- 教师视图数据只存在本机 `localStorage`，无登录、不上传服务器；清空后不可恢复。

## 阶段 3 新增：诚实性与性能打磨

### 首页文案与真实覆盖一致

首页不再写「8 个知识领域」。领域区改为 **7 个真实模块**，每一项都标出内置题数和任意题复算能力：

| 模块 | 内置题 | 任意题本地复算 | 首页标注 |
|---|---|---|---|
| 函数 | 1（函数值求解） | 函数代入 | 任意题：可本地复算 |
| 方程 | 1（一元二次方程） | 多项式方程求根与代回，不检查定义域 | 任意题：可本地复算 |
| 指数与对数 | 2（幂的运算、对数定义） | 不支持 | 任意题：实验性 · 仅 AI 推断 |
| 三角函数 | 2（弧度换算、特殊角求值） | 不支持 | 任意题：实验性 · 仅 AI 推断 |
| 数列 | 2（等差数列通项、前 n 项和） | 等差数列单项与求和 | 任意题：可本地复算 |
| 概率 | 2（两枚硬币、六面骰） | 不支持 | 任意题：实验性 · 仅 AI 推断 |
| 集合 | 2（并集、交集的补集） | 交、并、补 | 任意题：可本地复算 |

- 模块内的能力列表也改成题库实际覆盖的能力，例如函数只写「函数值求解、负数代入、符号处理」，不再声称能诊断定义域。
- 首屏、页脚把「OFFLINE」改为「LOCAL RULE ENGINE / NO AI KEY」「LOCAL CORE / NO API KEY REQUIRED」：核心诊断不需要 API Key；字体与插图在首次加载时需要网络，之后可由浏览器缓存。footer 正文已写明这一点。
- 幂运算案例的说明修正为「指数相加写成相乘 / 底数相加」，与两个真实错因模式一致。

### 配图改为本地静态资源

- 原首页 16 处 `trae-api-cn.mchost.guru` 运行时生图已全部移除。当前 15 张配图（5 个案例 + 3 张证据卡 + 7 个领域）使用原 prompt 重新生成一次，压缩为 WebP 后放在 `public/images/`，总体积约 564 KB。
- `src/data/site.ts` 只保存 `/images/...` 本地路径；`dist/images/` 随构建产物一起发布。页面断网刷新后插图仍可显示。
- 所有插图补了 `width`/`height` 与 `decoding="async"`，非首屏插图继续 `loading="lazy"`。

## 阶段 4 新增：多供应商模型接入

「供应商名称」「模型 ID」「接口协议」现在是三个独立配置。页面「AI 设置」可以继续使用站点默认配置，也可以选择「使用自己的 Key」，在火山方舟、DeepSeek、OpenAI、Anthropic（Claude）以及管理员登记的中转站之间切换。

- **两种协议**：OpenAI Chat Completions 与 Anthropic 原生 Messages。Base URL 保留 `/v1`、`/api/v3` 或中转站自定义前缀；Anthropic 使用 `x-api-key`、`anthropic-version`、顶层 `system` 和 `max_tokens`，只取 `text` 内容块，thinking 不进入诊断 JSON。
- **协议不等于模型名**：中转站即使提供名为 `claude-...` 的模型，也按管理员声明的协议调用；新增同协议中转站只需增加 `AI_PROVIDERS` 配置。
- **请求级配置**：每次请求独立解析供应商、模型和凭证，不修改进程全局变量；两个用户并发选择不同供应商时互不影响。
- **站点/自定义分离**：站点模式只提交公开的 `providerId`，地址、模型范围和 Key 由服务端决定；自定义模式的 Key 只存在当前页面内存，切换供应商即清除。
- **三种状态分开**：已填写、已启用、已实际连接是不同状态；只有用户主动点击「测试连接」或真实诊断成功后，才显示「已实际连接」。打开设置、切换下拉框不会产生付费模型请求。
- **模型 ID 可手填**：支持官方模型名、火山接入点 ID 和中转站别名；「读取模型列表」失败时保留手填，不影响使用。
- **图片能力按模型配置**：纯文本模型仍可正常诊断；图片识别失败会明确提示填写图片模型 ID 或改用支持图片的供应商。
- **错误不换供应商**：凭证无效、模型不可用、限流、超时、图片能力不足、响应格式错误分别提示；不会自动切到站点 Key，也不会把题目发给第二家。

> 当前验证状态：OpenAI / Anthropic 两种协议、四入口、路径前缀、并发隔离和错误矩阵均已用本地 mock 上游验证；**真实 OpenAI / DeepSeek / Anthropic / 中转站尚未联调（当前没有真实凭证），标记为待验证**。

## 使用自己的 API Key

阶段 2 之后，任意题诊断页新增「AI 设置」。阶段 4 将其扩展为多供应商面板。

- **只存在当前页面内存**：自定义 Key 不写入 `localStorage`、`sessionStorage`、Cookie、URL、日志、错误信息、分析事件或学习报告；刷新或关闭页面即清除，切换供应商时旧 Key 立即清空。
- **只在需要 AI 时转发**：命中内置 12 题时仍走本地规则，不发任何请求。只有规则无法判断、用户已启用自定义 Key 且实际发起 AI 调用时，Key 才通过 HTTPS 请求体发送给本站后端，再由后端请求所选供应商。
- **供应商、模型、协议分开选**：页面显示实际接收请求的域名、协议、文本模型和可选图片模型；模型 ID 可手填，也可点击「读取模型列表」尝试从供应商读取，失败时仍可手填。
- **启用 ≠ 连接成功**：点击「启用」只让设置生效；只有用户点击「测试连接」发送最小请求并收到有效响应，或真实诊断成功后才显示「已实际连接」。
- **无效 Key 不回退**：自定义 Key 被服务商拒绝时提示检查 Key，不会自动改用站点账户；限流、超时、断网时保留已填答案、步骤和已有规则结论。
- **并发隔离**：后端按单次请求解析供应商与凭证，不修改全局环境变量、不共享鉴权客户端；两个用户同时请求时各自使用自己的配置。
- **切换期间旧结果不污染新设置**：每次设置变化递增一个内存 `revision`；旧请求晚返回时不会把新供应商标成「连接成功」。

### 服务端配置（三套示例）

完整字段说明见 [.env.example](.env.example)。以下只放占位 Key，真实 Key 不要提交到仓库。

**1. 保留原火山方舟配置（旧变量）**

```powershell
$env:AI_BASE_URL = 'https://ark.cn-beijing.volces.com/api/v3'
$env:AI_MODEL = 'ep-xxxxxxxx'          # 火山控制台的接入点 ID 或模型名
$env:AI_VISION_MODEL = 'ep-yyyyyyyy'   # 可选，多模态接入点
$env:AI_API_KEY = '<服务端密钥>'
$env:AI_PROVIDER_NAME = '火山方舟'
node server.mjs
```

旧部署升级后不需要改前端；旧前端请求不带 `providerId` 时仍使用这个默认供应商。

**2. 用户自带 DeepSeek / OpenAI / Claude Key**

```powershell
# 不配置 AI_API_KEY，也不需要配置 AI_MODEL；
# 页面会列出内置的火山方舟、DeepSeek、OpenAI、Anthropic（Claude）入口。
node server.mjs
```

用户选择供应商后填写自己的模型 ID 和 Key，点「启用 → 测试连接」即可。模型 ID 以服务商控制台或文档为准：DeepSeek 常见为 `deepseek-chat` / `deepseek-reasoner`，OpenAI 常见为 `gpt-4o-mini` / `gpt-4o`，Anthropic 常见为 `claude-sonnet-4-5`，火山方舟使用控制台创建的 `ep-...` 接入点。页面里的示例 ID 只是占位建议，不保证你的账号可用。

如果还要兼容旧前端，可只配置一个默认模型、不配置站点 Key：

```powershell
$env:AI_MODEL = '<默认文本模型或接入点 ID>'
node server.mjs
```

**3. 管理员添加带路径前缀的中转站**

```powershell
$env:AI_PROVIDERS = '[{"id":"campus-relay","label":"校园中转站","protocol":"openai","baseUrl":"https://relay.example.edu.cn/ai/v1","textModels":["claude-sonnet-4-5-relay"],"visionModels":[],"apiKey":"","customKey":true,"jsonMode":"none","default":false}]'
node server.mjs
```

- `baseUrl` 必须是 HTTPS（本机 mock 可用 HTTP 回环地址）；`/ai/v1` 这样的路径前缀会保留，最终请求为 `https://relay.example.edu.cn/ai/v1/chat/completions`。
- 模型别名含 `claude` 不会改变协议；这里声明 `protocol: "openai"`，就按 OpenAI Chat Completions 发送。
- 声明 `protocol: "anthropic"` 时，服务端会请求 `<baseUrl>/v1/messages`（Base URL 已带 `/v1` 时不重复追加）。
- 站点模式需要默认 Key 时，在对应项里填写 `apiKey`；仍然只存在于服务端环境变量。
- 新增同协议中转站只需再加一个数组项，不需要改代码。

- `AI_MODEL` 为空且没有可用默认供应商时，`/api/health` 返回 `customKeyReady:false`；新前端仍会显示内置 BYOK 入口，旧前端会提示「站点尚未配置模型」。
- 只配置默认模型、不配置 `AI_API_KEY` 时，`/api/health` 返回 `ai:false`、`customKeyReady:true`；页面允许自定义模式，站点模式会提示未配置默认 Key。
- 线上 FunctionWeb 需要在服务端环境变量中配置同样的项；配置后无需改前端。

## 这次迭代改变了什么

- **正确中间步骤不再被判错。** 集合题先写 `A∩B={3,4}`、再写 `U\(A∩B)={1,2,5,6}`、最终答案 `{1,2,5,6}`，整题判为正确；只有学生停在 `A∩B={3,4}` 并把它当最终答案时，才提示“交集算对了，还差取补集”。
- **同一份推导的常见写法得到一致判断。** 对 `f(x)=x²-2x+3` 求 `f(-1)`，`f(-1)=1-2+3`、`f(-1)=1-2+3=2`、以及“先写正确代入、下一行写 `=1-2+3=2`”都会定位到实际出现符号错误的那一行，并说明 `-2×(-1)=+2`。
- **相同错答可以给出不同结论。** 甲写 `f(-1)=1-2+3=2`，定位第 1 行一次项符号；乙写 `f(-1)=1+2+3`、`1+2+3=2`，定位第 2 行最后加法。只填 `2`、不写步骤时，只列出两种待确认原因并追问“你代入后，-2x 这一项是多少？”，不标红任何一行。
- **学生修改后结论跟着变。** 修改答案或任意步骤会清除旧高亮、旧薄弱点和旧变式结果；重新提交后重新判定。最终答案正确但过程有明确错误时，分开显示“结果正确”和“这一步需要检查”，并允许针对这一步做变式。
- **变式反馈区分首次与重试。** 做对时显示“本次变式答对”，并标注“首次作答”或“第 N 次尝试”；报告统计“变式首次答对 X / 尝试 Y”，不把一次选择推断为长期掌握。

## 演示路径

1. 首屏读题：“两个人都答了 2，他们错在同一步吗？”点「比较两份草稿」。
2. 在 `#compare` 看甲、乙两份可编辑的演示草稿。两份都走正式诊断引擎，初始结论分别定位到第 1 行和第 2 行。
3. 改任意一行或最终答案，点「重新诊断」；旧结论先清除，再按新内容重新定位。点「恢复演示草稿」可回到初始样例。
4. 点「查看证据不足时会发生什么」，看到只填 `2` 时的两种待确认原因和追问，且没有红色步骤。
5. 滚动到 `#freeform` 任意题诊断：输入一道不在题库里的题（例如 `已知 f(x)=2x²+3x-1，求 f(2)`），填写答案和步骤，点「开始诊断」。结果卡左侧是 AI 理解，右侧是本地复算账本；可计算结论标「已核验」，冲突标红，无法复算标「AI 推断」。也可以上传图片先识别、确认后再提交。
6. 点「自己写一份」进入 `#practice`，选择题组，例如「函数与方程」。
7. 第 1 题答案填 `2`、步骤填 `f(-1)=1-2+3=2`，提交。诊断卡显示 `DIAGNOSED`，第 1 步被标红，引用学生原句并说明一次项符号。
8. 点「做一道变式，验证已掌握」，选正确答案后显示「本次变式答对」与「首次作答」。
9. 点「下一题」继续，完成后生成整组报告：正确率、平均用时、各题结论、变式首次答对/尝试、合并去重后的补习顺序、图谱汇总。
10. 报告页可「复制纯文本报告」或「只重做错题」。
11. 回到第 1 题把错行和最终答案都改对并重新提交，会判为正确，旧的错因、步骤高亮和变式结果全部清除。

「跳过」不计入错因；「我不会」记为未作答，同样不会被猜测错因。进行中的会话和历史记录存在 `localStorage`（键名带 `v1` 版本号），刷新后可以继续。

## 三条诊断路线

**离线（默认）**　规则引擎只依赖题库与错因模式，不需要网络或密钥（页面静态资源首次加载除外）。规则无法匹配时返回「证据不足」，保留学生原句，给出一个具体追问，不编造知识点。

**任意题 AI + 本地核验**　题目没有命中内置 12 题时，服务端模型输出严格 JSON；前端再用本地规则逐条复算。核验覆盖函数代入、四则运算/等式链、集合运算、一元二次方程根、等差数列求和。一致标「已核验」，不一致标「冲突」并以复算结果为准，无法复算标「AI 推断，未核验」。模型输出结构不合格时重试一次，仍不合格就返回「证据不足」，页面不报错。超时、限流、断网、未配置都有明确提示。

**可选 AI 兜底**　内置题规则返回 `unknown` 时，页面才会尝试请求服务端模型；未配置、断网、超时（8 秒）或返回结构不合格时静默保留规则结论，页面不报错。AI 结果标记为「AI 诊断」，置信度最高为 `medium`，且只会保留知识图中真实存在的节点 ID。

使用 Node.js 20 或更高版本。服务端不依赖第三方 AI SDK：用 Node 内置 `fetch` 直接调用供应商协议，避免为了两种协议引入整套框架。`server.mjs` 提供：

- `GET /api/health`：保留 `{ ok, ai, model, visionModel, vision, provider, customKeyReady }`，新增 `customKeyAvailable`、`defaultProviderId`、`providers[]`。`providers[]` 只包含公开信息：id、名称、协议、实际域名、路径前缀、模型范围、是否有站点 Key、是否允许自定义 Key；不包含任何 Key。
- `POST /api/diagnose`：规则 `unknown` 时的旧 AI 兜底，8 秒超时。
- `POST /api/freeform-diagnose`：任意题结构化诊断；严格校验模型返回，失败重试一次，仍不合格返回 200「证据不足」。
- `POST /api/freeform-variants`：补充生成同错因变式候选；候选答案仍需前端本地复算后才会展示。
- `POST /api/recognize`：图片 OCR；只接受 data URL，识别结果回填后由学生确认。
- `POST /api/ai/test`：用户主动点击「测试连接」时才调用，向当前协议和模型发送一个最小请求并验证有效文本响应；不参与诊断，也不产生诊断提示词。
- `POST /api/ai/models`：用户主动点击「读取模型列表」时才调用；失败返回 200 `{ available:false, error:"models-unavailable" }`，前端保留手填，不影响使用。
- 若存在 `dist/`，同时作为静态服务器，访问 `http://127.0.0.1:8787` 即可预览构建产物。

四个业务入口的公共请求字段：`credentialMode: "site" | "custom"`、`providerId`；自定义模式再带 `apiKey`、`model`（图片识别可带 `visionModel`）。站点模式会忽略客户端提交的 `model`，只使用服务端配置；请求体出现 `baseUrl`、`endpoint` 等地址覆盖字段会被 400 拒绝；未知 `providerId`、非法模型 ID、未登记的协议同样会被拒绝。

凭证只在单次请求内解析：站点模式使用服务端配置的站点 Key，自定义模式只使用请求体里的 `apiKey`；每次请求生成独立配置对象，不修改进程全局变量。错误码区分 `custom-key-invalid`、`custom-key-required`、`unknown-provider`、`model-not-found`、`rate-limited`、`timeout`、`vision-model-required`、`truncated`、`upstream-redirect`、`invalid-response`、`invalid-schema` 等；错误信息不包含凭证。携带凭证的请求使用 `redirect: "manual"`，不会跟随跳转到其它域名。服务端不记录请求体或 Key。

开发模式下 Vite 已把 `/api` 代理到 `http://127.0.0.1:8787`（可用 `PORT` 环境变量修改服务端口）。两个终端分别运行 `node server.mjs` 与 `npm run dev` 即可联调；只运行 `npm run dev` 时任意题请求会失败，页面明确提示，内置 12 题仍可用。

## 引擎与数据

- `src/data/knowledge.ts`：12 道题、18 个知识节点与 16 条依赖边（图无环）。
- `src/data/practiceRules.ts`：25 个错因模式，每题至少 2 个；每个模式含答案特征、步骤特征、薄弱节点、补习步骤和一道变式题。集合题的两个“漏做/多做最后一步”模式带 `terminalOnly`，只有停在该中间结果时才构成错误。
- `src/engine/normalize.ts`：答案归一化（全角、上标、`×`/`·`、集合顺序、`π`/`√` 等）。
- `src/engine/stepAnalysis.ts`：有限算式求值与等式链分析。支持负数括号、幂、乘除、隐式乘法（如 `2(-1)`）和简单分步等式；无法可靠解释的自然语言返回 `null`，由上层保留原文并说明不确定。
- `src/engine/diagnose.ts`：`diagnose(questionId, answer)`，保持原有签名与行为；`buildLearningPath` 负责合并去重排序。
- `src/engine/attempt.ts`：`diagnoseAttempt({ questionId, finalAnswer, steps })`。返回 `status`（`correct / diagnosed / process-error / unknown`）、`firstWrongStepIndex`（明确不成立的步骤）、`focusStepIndex`（需要查看的步骤，漏步时指向正确中间步骤）、`stepQuote`（学生原句）、`alternativePatternIds`（待确认原因）、`probe`（区分原因的追问）、`processNote`。
- `src/engine/session.ts`：`summarizeSession(attempts)` 生成整组报告；`summarizeDiagnoses(records)` 汇总任意题诊断并合并去重薄弱节点与知识点文本。
- `src/engine/calcVerifiers.ts`：任意题核验的独立计算器。函数代入、四则运算/等式链、集合运算、一元二次/一元一次多项式方程求根、等差数列单项/求和；只对能可靠复算的结论给出 `verified / conflict`，其余返回 `unverified`。
- `src/engine/verify.ts`：把 AI 结论逐条对照学生原文与题干，校验引用原句和步骤序号，生成三态核验账本；冲突时以复算结果为准，无法复算的定性错因保持“AI 推断”。
- `src/engine/variant.ts`：变式候选复算闸门。只接受能从题干独立算出答案的候选；不通过就丢弃，并由调用方补充生成。
- `src/engine/variantReview.ts`：变式答错后的错因对比。先比知识节点，再比知识点文本，证据不足时返回“无法判断”。
- `src/engine/teacher.ts`：教师视图 CSV 的导出、解析、去重与 Top 3 错因聚合；纯函数，不依赖 DOM。
- `src/services/freeformRecords.ts`：自由题诊断记录的本机持久化与同题去重。
- `src/engine/freeform.ts`：内置题保守匹配与规则结果转换；命中内置题时不发请求。
- `src/engine/freeformSchema.ts`：严格校验模型返回的任意题诊断与 OCR 结构；任何结构不合格都降级为“证据不足”。

判定优先级：明确不成立的步骤（`high`）> 终态型漏步/多做一步（`high`，但不标红正确中间步骤）> 仅最终答案唯一匹配（`medium`）> 答案正确但过程错误（`process-error`）> 同一答案多种原因（`unknown`，列候选并追问）> 证据不足（`unknown`）。

## 已知边界

- 内置 12 题仍只靠规则；规则无法匹配时保留“证据不足”，不猜知识点。
- 任意题核验层只覆盖五类可复算结论：函数代入、四则运算/等式链、集合运算、一元二次/一元一次多项式方程、等差数列求和。其他题型（三角恒等变换、含参讨论、立体几何证明、复杂不等式等）只能标“AI 推断，未核验”。
- 方程根核验只做多项式求根/代回，不检查定义域与增根；含除法或多个字母的方程退回逐根代回，无法确认时标未核验。
- 自然语言步骤不做语义猜测：保留原句、说明不确定、给出一个具体追问。
- 同一最终答案对应多种原因时，只列候选，不据此确认薄弱点；需要学生补步骤或回答追问。
- AI 的定性错因即使数值结论已核验，也不等于“错因已被证明”；界面会分别显示“已核验”和“AI 推断”。
- 一次变式只记录“本次变式答对”，不推断长期掌握；真实掌握情况需要多次、间隔性的验证。
- 任意题变式只在能独立复算的题型内生成；三角函数、证明、含参讨论等题型会显示“没有找到可通过本地复算的变式”，不会展示未经核验的题。
- 变式答错后的“错因仍在 / 出现新问题”来自两次 AI 诊断的知识点对比，是线索而不是已证明结论；界面始终标注“未经独立核验”。
- 教师视图只聚合 CSV 里的真实字段；没有真实报告时统计为空，不生成虚构学生或准确率。数据仅在本机，换设备不会同步。
- 自定义 Key 只保存在当前页面内存；刷新、关闭页面、切换供应商或点击「清除」后不可恢复。用户可以从服务端登记的供应商中选择并手填模型 ID，但不能自行指定 Base URL；站点模式仍由服务端决定地址、模型范围和 Key。
- 内置的 OpenAI / Anthropic / DeepSeek 示例模型 ID 只是可编辑建议，不保证你的账号可用，以服务商控制台为准；「读取模型列表」也可能失败，此时必须手填模型 ID。
- 自定义 Key 的「已实际连接」只表示服务商对最小测试请求或一次真实诊断返回了有效响应；一次变式或单次诊断的结果仍受核验层和证据边界限制。
- 阶段 4 的协议验证是本地 mock，不是真实供应商联调；真实模型是否接受 `response_format`、温度、图片内容块等参数，仍需各自账号实测。
- 首页 7 个模块只代表内置题库的覆盖范围，每个模块 1–2 题，不代表完整高中数学；三角、概率、指数与对数的任意题只标“AI 推断”，首页标为实验性。
- 首页插图由文本生图模型生成一次后本地化，画面中的抽象符号不是可读数学内容，也不参与诊断。
- three.js 3D 场景只在桌面端空闲后加载；移动端与减少动效使用静态 SVG，不影响诊断能力。
- Google Fonts 首次加载需要网络，缺失时回退系统字体。“无需 API Key”不等于整页完全离线；核心规则诊断不依赖网络。
- Lighthouse 数字是 2026-11-25 本机单次测量，不作为线上性能承诺。
- 未实现登录、排行榜、跨设备同步；这些不是本次演示的前提。

- 原有四组回归场景保持不变：
  1. 集合题正确中间步骤 + 正确补集 → `correct`，不标红；停在交集 → 提示还差补集，中间步骤不标红。
  2. 三种函数题写法 → 都定位到实际符号错误行；整行正确算式 → 不误判。
  3. 甲/乙同答 `2` → 不同 `matchedPatternId`、不同错行、不同改正建议；只填 `2` → `unknown`、两种候选、追问、不标红。
  4. 改对错行与答案后重新提交 → 旧高亮/薄弱点/变式结果清除；最终答案正确但过程错误 → `process-error`，可做变式。
- 任意题入口：
  1. 命中内置题 → 规则诊断，不发请求；界面标“内置题 · 规则诊断”。
  2. 非题库题 → AI 结果卡 + 本地复算账本；三态可一眼区分。
  3. AI 算错 → 显示“AI 结论与复算冲突”，采纳复算值，保留 AI 原答案。
  4. 无法复算 → 只标“AI 推断，未核验”，置信度最高 `medium`。
  5. 未配置 / 超时 / 限流 / 断网 → 明确提示，不白屏；内置 12 题仍可用。
  6. 图片上传 → OCR 回填后必须人工确认，再提交。
- 阶段 2：
  1. 任意题诊断后最多展示 2 道同错因变式；答案错误的候选被丢弃并触发补充生成，最终全部带“答案已复算”。
  2. 复算不通过的题不展示；不足 2 道时如实说明，不用未核验题凑数。
  3. 变式答错 → 本地先判错，再出现“错因很可能仍在 / 原错因未复现，出现新问题 / 无法可靠判断”三选一，并附来源说明。
