# 知识漏洞侦探

一个适合在 TRAE 校园比赛现场演示的初中数学错题诊断网页。学生输入题目和自己的作答，沿知识依赖图找到可能出错的一步，按建议补习，再用一道变式题检查理解。

例如，学生把 `2(x − 3) = 10` 解成 `x = 6.5`。如果展开时写成 `2x − 3 = 10`，后面的计算恰好会得到这个答案。网页据此提示先检查乘法分配律。学生只填最终答案时，这个解释仍是一个待验证的猜想。

## 运行作品

**现场离线演示**　用浏览器打开本目录的 `index.html`，页面会预览「去括号解方程」。点「开始诊断」，报告的来源标记会从「案例预览」变成「本地诊断」。点击图中的「乘法分配律」可查看知识点，关闭弹窗，再向下阅读「可能的错因」「建议补习顺序」，完成「验证一下」。要换题，点「载入案例」。三个内置案例均可在本地运行，无需安装依赖、登录或获取密钥。离线诊断使用题库中的已知错因。

**自拟题目接入 AI**　使用 Node.js 20 或更高版本，以及支持 Chat Completions 和 JSON 输出的模型服务。`AI_BASE_URL` 默认为 `https://api.deepseek.com`。使用其他服务时，在同一个终端设置 `AI_BASE_URL` 为供应商给出的兼容基地址，包含其要求的版本路径。在项目目录的 PowerShell 中依次运行以下三行，按提示输入模型 ID 和密钥。

```powershell
$env:AI_MODEL = Read-Host '模型 ID'
$env:AI_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'API 密钥' -AsSecureString)).Password
node server.mjs
```

打开 [本地网页](http://127.0.0.1:4173)。页首显示「AI 接口已配置」后，可试自拟题 `解方程：3(x − 4) = 15`，作答填 `3x − 4 = 15，所以 x = 19/3`。内置规则无法判断时，网页会把题目和作答发给所配置的模型。看到报告标记「AI 诊断」后，检查它是否识别了展开式中漏乘的常数项。赛前把内置题也跑一遍，现场断网即可切回离线演示。

## 两人怎样用完这 120 分钟

**队员 A 管“为什么这样判断”。** 负责题目、错因规则、知识关系和 AI 服务，主要维护 `engine.js`、`server.mjs`。每组案例交付题目、典型错答、可能根因、对应证据、知识关系、补习步骤和一道验证题。

**队员 B 管“学生怎么用”。** 负责输入、诊断结果、依赖图、验证题交互和路演，主要维护 `index.html`、`styles.css`、`app.js`，以及绘制知识依赖图的 `graph.js`。B 操作演示电脑，A 负责讲清数学依据和诊断边界。

| 比赛用时 | A · 诊断与内容 | B · 交互与演示 | 到点交接或验收 |
| --- | --- | --- | --- |
| 0–10 分钟 | 手算第一题的正确答案和典型错答 | 画出输入、依赖图、补习、验证四个画面状态 | 两人锁定首题与结果字段，约定用同一份样例数据联调 |
| 10–35 分钟 | 完成首题的错答、正确、证据不足三条分支 | 用样例数据接通输入、提交和结果展示 | 第 35 分钟由 A 交付可调用的本地诊断函数，B 用实际返回值替换样例 |
| 35–65 分钟 | 补齐另外两题和验证题，开发可选 AI 接口 | 接通知识节点、补习顺序和验证题反馈 | 第 65 分钟双击网页，完整走通首题后冻结输入输出字段 |
| 65–90 分钟 | 核对换答案、陌生题以及模型失败时的反馈 | 检查手机宽度、长输入和修改答案后重新提交 | 两人交换电脑，各自从头走一遍，优先修复会误诊或打断演示的问题 |
| 90–105 分钟 | 修正数学或服务错误，核对三例的讲解 | 修正交互问题，按下方脚本计时排练 | 第 105 分钟冻结功能。在线接口未就绪时选定离线路线 |
| 105–120 分钟 | 在交付目录重新打开网页，按验收清单复测 | 在演示电脑排练一次，检查投屏字号和开场页面 | 两人核对入口、源码、说明齐全，再按现场要求提交 |

**联调约定。** 前端把题目与作答交给 `DetectiveEngine.diagnose(question, answer)`，先看结果状态 `diagnosed`、`correct` 或 `unknown`，再展示对应内容。诊断结果包含可能根因及依据、知识节点与连线、补习顺序和验证题。A 管字段含义，B 管显示方式。改字段前先用第一题对照一次。

## 交付验收

- [ ] 在演示电脑断网打开 `index.html`。分别用方程题的 `6.5`、分数加法的 `2/5`、直角边为 6 和 8 的斜边题的 `100` 进行诊断，检查每条补习路径都对应当前错因。
- [ ] 第一题提交 `x = 6.5`，读出从 `2x − 3 = 10` 到该答案的关系。再提交正确答案 `x = 8`，确认上一次的错因已清除。
- [ ] 保留第一题，改答 `2x+6=10，所以 x=2`，检查解释是否引用学生写出的这一步，并识别常数项的符号错误。
- [ ] 验证题分别选择正确和错误选项，检查反馈能解释这道变式题。修改题目或留空后重新提交，确认旧诊断不会冒充新结果。
- [ ] 用手机宽度打开页面，能读清图中关系并完成验证。若准备演示在线路线，用一题自拟题核验实际模型返回，再演练一次接口不可用时切回内置题。

## 90 秒现场讲稿

| 时间 | 操作与台词 |
| --- | --- |
| 0–15 秒 · B | 选中方程例题，展示 `x = 6.5`。“老师在这道题旁打了叉。学生回家复习，到底该重做整章，还是先练一个知识点？” |
| 15–35 秒 · A | B 提交错答。A 指向诊断依据。“如果括号外的 2 只乘了 x，式子就成了 2x − 3 = 10，算到底正好是 6.5。这给了我们一个值得先查的线索。” |
| 35–60 秒 · B | 指向图中的薄弱点，再看补习步骤。“用展开括号的办法解这道题时，第一步就用到了分配律。我们先补这一小步，再回到原题。” |
| 60–80 秒 · A | B 操作验证题，选择 `3y − 12`。A 解释选项。“换成 3(y − 4)，括号外的 3 也要乘上 −4。这一题单独检查刚才那一步，学生能立刻验证自己是不是理解了。” |
| 80–90 秒 · B | 回到原题，提交 `x = 8`。“从一道错题出发，学生知道下一步该练什么，也能马上检查自己学会了没有。” |
